# Профиль проекта

Главный файл параметров текущего проекта 1С. Правила в `rules/` и скиллы в `skills/` ссылаются на параметры отсюда (`{PREFIX}`, `{PLATFORM_VERSION}` и др.). Значения не угадывать: если параметр пуст, действует поведение из колонки «Если пусто».

Эталонный шаблон и примеры конфигурации под различные проекты находятся в `project-profile.example.md`.  
Сведения о структуре репозитория, зонах кода и тестах — в `rules/project-context.md`.

## Параметры проекта

| Параметр | Значение | Назначение | Если пусто |
|---|---|---|---|
| `{PREFIX}` | `смк_` | Префикс для новых объектов метаданных, реквизитов типовых объектов, элементов форм, ролей и подсистем | Новые объекты создаются без префикса. `{PREFIX}` в шаблонах превращается в пустую строку |
| `{PLATFORM_VERSION}` | `8.3.27` | Версия платформы 1С:Предприятие (и режим совместимости конфигурации). Определяет доступные языковые конструкции (`Асинх` / `Ждать` с 8.3.18, асинхронный HTTP с 8.3.21) | Спросить у пользователя при написании асинхронного кода, иначе считать 8.3.18+ |
| `{EDT_PROJECT_FORMAT}` | `src/cf/src` | Структура каталогов исходных кодов 1С (EDT) в репозитории (`src/cf/src`, `src/configuration`, корень `.`) | Определить каталог по расположению `Configuration.mdo` |
| `{CONFIGURATION_TYPE}` | `ERP` | Тип прикладного решения (ERP, КА, УТ, БП, ЗУП, УНФ, Самописная) | Считать конфигурацию произвольной |
| `{USES_BSP}` | `Да` | Использование Библиотеки Стандартных Подсистем (БСП) | `Да`, если найден общий модуль `ОбщегоНазначения`, иначе `Нет` |
| `{LOCK_MODE}` | `Managed` | Режим управления транзакционными блокировками данных (`Managed` / `Automatic`). См. `rules/locks-and-transactions.md` | `Managed` |
| `{TEST_FRAMEWORKS}` | `YAxUnit, Vanessa Automation` | Используемые инструменты тестирования (`YAxUnit`, `Vanessa Automation`, `Отсутствуют`) | `Отсутствуют` |
| `{NEW_OBJECTS_IN}` | `main_configuration` | Размещение вновь создаваемых объектов: `main_configuration` (в основной конфигурации) или `extension` (в расширении) | `main_configuration` |

## Правила применения параметров

### 1. Префикс метаданных (`PREFIX`)

`PREFIX` — это рекомендация, а не жесткое требование. Его отсутствие не является дефектом.

- **`PREFIX` задан** — новые объекты метаданных, реквизиты типовых объектов, элементы типовых форм, роли и проектные подсистемы создаются с этим префиксом. Внутри собственных объектов реквизиты создаются **без** префикса (см. `rules/metadata-naming.md`).
- **`PREFIX` пуст** — новые объекты, реквизиты, табличные части, элементы форм, роли и подсистемы создаются без префикса. Остальные правила именования (`rules/metadata-naming.md`) действуют. Коллизии имен с типовыми объектами — забота разработчика: агент указывает на замеченную коллизию, но префикс сам не придумывает.

### 2. Версия платформы (`PLATFORM_VERSION`) и асинхронность

- При значении `>= 8.3.18` в клиентском коде предпочтителен асинхронный синтаксис: `Асинх`, `Ждать`, функции с суффиксом `Асинх` (`ВопросАсинх`, `ПредупреждениеАсинх`, `НайтиФайлыАсинх`).
- При значении `< 8.3.18` (а также в модулях расширений с пониженным режимом совместимости) ключевые слова `Асинх` / `Ждать` не используются, диалоги оформляются через `ОписаниеОповещения` и `Показать*`. Подробнее — в `rules/async-methods.md`.

### 3. Библиотека Стандартных Подсистем (`USES_BSP`)

- При значении `Да` (`Истина`) чтение реквизитов объектов выполняется строго через функции БСП `ОбщегоНазначения.ЗначениеРеквизитаОбъекта*`, для длительных операций используется подсистема `ДлительныеОперации`, для строковых операций — `СтроковыеФункцииКлиентСервер`. Прямое чтение через точку от ссылки на сервере запрещено.
- При значении `Нет` (`Ложь`) функции БСП не вызываются, чтение выполняется точечными запросами или специализированными модулями проекта.

### 4. Режим блокировок (`LOCK_MODE`)

- При `Managed` перед записью наборов записей или чтением критичных остатков в транзакции обязательна явная установка управляемой блокировки (`БлокировкаДанных`). Подробнее — в `rules/locks-and-transactions.md`.
- При `Automatic` платформа управляет блокировками автоматически через механизмы СУБД, однако длительность транзакций должна оставаться минимальной.

## Окружение

| Что | Значение |
|---|---|
| Формат исходников | EDT (каталог определяется `{EDT_PROJECT_FORMAT}`) |
| Конфигурация | Тип: `{CONFIGURATION_TYPE}`, режим совместимости: `{PLATFORM_VERSION}`, режим блокировок: `{LOCK_MODE}`, БСП: `{USES_BSP}` |
| Размещение доработок | `{NEW_OBJECTS_IN}` (основная конфигурация или расширение) |
| Тестирование | `{TEST_FRAMEWORKS}` (структура и соглашения описаны в `rules/project-context.md`) |
| Функциональные роли инструментов | Проверка BSL (BSL LS / синтакс-контроль), чтение структуры метаданных, справка по API платформы, интеграция с Git и трекером задач (подробнее см. `workflow/local.md` и `workflow/bsl-mcp.md`) |

## Настройки процесса

Всё, что касается веток, задач, ревью и заметок, вынесено в отдельный модуль `workflow/` и настраивается отдельно. См. `workflow/README.md`.
