# Правила разработки 1С - входной файл

Этот файл читает любой ИИ-агент (Cursor, Claude Code, Codex, Copilot и др.). Он ничего не дублирует, а говорит, какие правила и навыки когда открывать. Все правила лежат в `rules/` в обычном markdown, исполняемые навыки - в `skills/`, регламенты процессов - в `workflow/`.

## Как пользоваться

1. Перед написанием или ревью BSL-кода открыть правила и навыки по теме из таблицы ниже. Не полагаться на память.
2. Параметры проекта (префикс, версия платформы, БСП, режим блокировок) берутся из `project-profile.md`. Значения не угадывать.
3. Перед правкой любого файла определить зону кода (типовой код, наш проектный код, сторонние библиотеки, фреймворк тестов, проектные тесты) по `rules/project-context.md`.
4. Загружать только нужные файлы, не весь набор «на всякий случай».
5. При решении прикладных типовых задач подключать соответствующие специализированные навыки из `skills/`.
6. Правила процесса (ветки, задачи, ревью MR/PR, заметки) лежат в `workflow/`. Общие параметры заполнены в `workflow/README.md`. Личные настройки (`{РАБОЧАЯ_КОПИЯ}`, `{REVIEW_WORKTREE}`, `{NOTES_STORAGE}`) каждый разработчик задает у себя в `workflow/local.md` (не коммитится, шаблон - `workflow/local.example.md`). Незаполненные параметры агент не выдумывает, а уточняет у пользователя.

## Субагенты

В каталоге `agents/` описаны субагенты: работают в отдельном контексте, только на чтение, возвращают отчет по общему контракту `agents/_contract.md` (ссылки `файл:строка`, Confidence, обязательный раздел «Что не проверено»). Адаптеры для автоматической загрузки - `.cursor/agents/` (Cursor) и `.claude/agents/` (Claude Code). Когда делегировать и как собирать конвейеры - `workflow/subagents.md`.

| Субагент | Файл | Условия вызова |
|---|---|---|
| `onec-explorer` | `agents/onec-explorer.md` | Разведка перед доработкой: цепочки вызовов, места использования, подписки, перехваты в расширениях |
| `onec-reviewer` | `agents/onec-reviewer.md` | Код-ревью diff перед коммитом и MR/PR |
| `onec-query-auditor` | `agents/onec-query-auditor.md` | Аудит запросов в модулях или diff |
| `onec-metadata-validator` | `agents/onec-metadata-validator.md` | Целостность `*.mdo` и `Form.form`, дубликаты UUID |
| `onec-bsp-checker` | `agents/onec-bsp-checker.md` | Проверка вызовов БСП по справочнику `bsp-api.py` |
| `onec-verifier` | `agents/onec-verifier.md` | Независимая перепроверка отчетов субагентов, финальный шаг конвейера |

Субагенты не запускают других субагентов и не меняют файлы: конвейер собирает и правки вносит главный агент.

## Самое частое, что нарушают

- Типовой код конфигурации править минимально. Сторонний библиотечный код и фреймворки без явного запроса не менять.
- Отступ - табуляция, одна инструкция на строку.
- Запрещены: тернарный оператор `?(...)`, `Выполнить()` / `Вычислить()` без обоснования, прямой `Сообщить()`, `Попытка...Исключение` вокруг чтения и записи в БД без обоснования, сравнение булевых с `Истина` / `Ложь`, Yoda-синтаксис, венгерская нотация, магические числа, локальные переменные с именами из глобального контекста.
- Доступ к реквизитам ссылки - через функции БСП `ОбщегоНазначения.ЗначениеРеквизитаОбъекта*` при `{USES_BSP} = Да`, не через точку.
- Комментарии объясняют «почему», а не «что». Баннеры автор/дата/история запрещены.
- В коде 1С и пользовательских текстах не использовать букву «ё» и длинное тире «—», только дефис.
- Области модулей - по канону из `rules/module-structure.md`, вложенные области внутри процедур запрещены.

## Правила, строже стандартов ИТС

Часть правил намеренно строже официальных стандартов 1С ИТС. Такие места помечены **`[Правило проекта - строже стандарта ИТС]`**. Обсуждая их, называть это решением проекта, а не требованием ИТС. При вопросе явно сказать, чем правило отличается от стандарта. Молча ослаблять такие правила «под ИТС» нельзя: поднять вопрос и дать решить пользователю.

## Функциональные возможности MCP-окружения и порядок действий при их отсутствии

Инструменты MCP сопоставляются с функциональными ролями (capability-based):

| Роль | Назначение | Действия при отсутствии инструмента |
|---|---|---|
| `bsl-diagnostics` | Проверка синтаксиса и статический анализ BSL (BSL LS `analyze_file`) | Запуск CLI `bsl-language-server`, скриптов синтакс-контроля проекта или ручной аудит по `rules/coding-standards.md` с фиксацией в отчете |
| `metadata-provider` | Чтение структуры метаданных конфигурации и расширений | Анализ дескрипторов метаданных `*.mdo` и исходников в каталоге EDT |
| `platform-docs` | Справка по API платформы и типам данных | Использование синтакс-помощника платформы, документации ИТС и параметров `{PLATFORM_VERSION}` |
| `git-host` | Операции с MR/PR (GitLab / GitHub) | Консольные команды `git` (или `gh`), ручное чтение веток и формирование отчета в markdown |
| `task-tracker` | Получение требований и критериев задачи (Jira, YouTrack, Kaiten) | Получение требований и критериев приемки из вводного сообщения пользователя |

При отсутствии любых MCP-инструментов агент продолжает работу автономно, ориентируясь на файлы репозитория и правила пакета.

## Как подключить к разным агентам

Пакет нейтрален к харнессам и платформам запуска:

| Агент / Среда | Файл адаптера | Что настроено |
|---|---|---|
| **Claude Code** | `CLAUDE.md`, `.claude/agents/` | Подключает `@AGENTS.md`, регистрирует доступные навыки в `skills/` и субагентов |
| **Cursor** | `.cursorrules` / `.cursor/rules/bsp-edt.mdc`, `.cursor/agents/` | Активирует стандарты для файлов `*.bsl`, `*.os`, `*.mdo`, `*.xml`, регистрирует субагентов |
| **Codex / GitHub Copilot** | `.github/copilot-instructions.md` | Передает инструкции по BSL, структуре метаданных и навыкам |

Пакет лежит в корне репозитория и коммитится вместе с проектом: `AGENTS.md`, `CLAUDE.md`, `.cursorrules`, `.cursor/rules/`, `.cursor/agents/`, `.claude/agents/`, `.github/`, `project-profile.md`, `agents/`, `rules/`, `workflow/`, `skills/`. Личные настройки и токены (`.mcp.json`, `workflow/local.md`, `.env`) исключены через `.gitignore`.
