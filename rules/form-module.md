Этот файл владеет темами, специфичными для модуля формы: подключение обработчиков событий, зарезервированные имена, данные формы. Все остальное делегируется единственному источнику.

## Клиент-серверное взаимодействие и директивы компиляции

Единственный источник - `architecture.md`, раздел «Клиент-серверное взаимодействие»; примеры и приоритеты - `anti-patterns.md` §6-§7. Здесь не дублируется.

## Добавление обработчиков событий формы

> **ВАЖНО.** Процедура-обработчик в `Form.Module.bsl` ничего не делает, пока привязка события не добавлена в XML формы (обычно `Form.xml` в родительском каталоге кода модуля).

Привязки событий в XML выглядят так:

```xml
<Events>
	<Event name="OnOpen">ПриОткрытии</Event>
	<Event name="BeforeWrite">ПередЗаписью</Event>
	<Event name="OnCreateAtServer">ПриСозданииНаСервере</Event>
</Events>
```

Значение внутри тега `<Event>` - имя процедуры-обработчика в модуле формы.

Частые события формы с условными именами обработчиков (**неполный набор**: платформа предоставляет десятки событий формы, элементов и таблиц):

| Имя события в XML | Русское имя обработчика | Описание |
|----------------|----------------------|-------------|
| `OnOpen` | `ПриОткрытии` | Клиент, при открытии формы |
| `OnClose` | `ПриЗакрытии` | Клиент, при закрытии формы |
| `BeforeWrite` | `ПередЗаписью` | Клиент, перед записью |
| `AfterWrite` | `ПослеЗаписи` | Клиент, после записи |
| `OnCreateAtServer` | `ПриСозданииНаСервере` | Сервер, создание формы |
| `BeforeWriteAtServer` | `ПередЗаписьюНаСервере` | Сервер, перед записью объекта |
| `OnWriteAtServer` | `ПриЗаписиНаСервере` | Сервер, внутри транзакции записи |
| `AfterWriteAtServer` | `ПослеЗаписиНаСервере` | Сервер, после записи |
| `OnReadAtServer` | `ПриЧтенииНаСервере` | Сервер, при чтении объекта |

Не путать клиентское событие формы `AfterWrite` / `ПослеЗаписи` с событием модуля объекта `ПриЗаписи` (`OnWrite`): это разные события в разных модулях.

### Как получить полный список событий

Полный и авторитетный список доступных событий **не брать** из таблицы выше. Использовать:

- синтакс-помощник платформы и справку по конкретному типу элемента формы (форма, поле формы, таблица формы, кнопка формы);
- уже существующую похожую форму: у каждого элемента в ее XML перечислены подключенные события с именами обработчиков;
- поиск по конфигурации, чтобы найти образцовые формы, уже использующие нужное событие;
- инструменты вашего агента для метаданных и справки платформы, если они доступны.

## Зарезервированные имена

В модулях форм 1С локальные переменные **не должны** называться по стандартным свойствам элементов формы:

- `ПараметрыВыбора` (ChoiceParameters)
- `СвязиПараметровВыбора` (ChoiceParameterLinks)
- `СписокВыбора` (ChoiceList)
- `ПараметрыОтбора` (Filter)
- `ОтборСтрок` (RowFilter)

> Список составлен по практическому опыту и может быть неполным. При подозрении на конфликт имен проверить в Конфигураторе.

**Почему.** В контексте `&НаСервере` модуля формы платформа может интерпретировать `ПараметрыВыбора = ...` как попытку установить свойство элемента формы, а не присвоить локальную переменную. Если тип значения не соответствует ожидаемому (`ФиксированныйМассив(ПараметрВыбора)`), возникает ошибка выполнения «Несоответствие типов».

**Как называть.** Использовать конкретные, контекстные имена:

```bsl
// Плохо:
ПараметрыВыбора = Новый Массив;

// Хорошо:
ПараметрыВыбораСтатьи = Новый Массив;
ПараметрыВыбораНоменклатуры = Новый Массив;
```

## Данные формы

- Использовать `ДанныеФормыВЗначение()` / `ЗначениеВДанныеФормы()` для преобразования между данными формы и реальными объектами.
- Помнить, что реквизиты формы - не то же самое, что реквизиты объекта: это представления, специфичные для формы.
- При использовании директив из таблицы директив (`&НаКлиенте`, `&НаСервере`, `&НаСервереБезКонтекста`, `&НаКлиентеНаСервереБезКонтекста`) всегда проверять доступность методов, функций, процедур, реквизитов и элементов в контексте директивы.
