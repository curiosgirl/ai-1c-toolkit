# Антипаттерны 1С и рекомендации по производительности

> **Владение.** Этот файл владеет **каталогом** антипаттернов: приоритет, признаки, шаблоны «было/стало». Сами нормативные правила по запросам (нет запросов в циклах, параметризация, псевдонимы `КАК`, фильтры виртуальных таблиц через параметры, промежуточная переменная результата, именование `ВТ_*`, `ПЕРВЫЕ N`) принадлежат `architecture.md`, раздел «Запросы»; запрет обращения через точку - `architecture.md` §4. При конфликте побеждает файл-владелец: правила правятся там, примеры здесь.

## Критические антипаттерны (исправлять обязательно)

### 1. Запрос в цикле

**Влияние:** O(n) обращений к базе вместо O(1)
**Приоритет:** CRITICAL

```bsl
// ❌ CRITICAL: N обращений к базе
Для Каждого Строка Из Данные Цикл
    Запрос = Новый Запрос("ВЫБРАТЬ ... ГДЕ Ссылка = &Ссылка");
    Запрос.УстановитьПараметр("Ссылка", Строка.Ссылка);
    РезультатЗапроса = Запрос.Выполнить();
КонецЦикла;

// ✅ ОПТИМАЛЬНО: одно обращение к базе
Запрос = Новый Запрос;
Запрос.Текст =
"ВЫБРАТЬ ...
|ГДЕ
|   Ссылка В (&СписокСсылок)";
Запрос.УстановитьПараметр("СписокСсылок",
    Данные.ВыгрузитьКолонку("Ссылка"));
РезультатЗапроса = Запрос.Выполнить();
```

### 2. Прямое обращение к реквизитам (через точку)

**Влияние:** загружает объект целиком из базы
**Приоритет:** CRITICAL
**Примечание:** по умолчанию в проекте это жесткий запрет вне тривиальных обработчиков с единичным вызовом. **[Правило проекта - строже стандарта ИТС]**: ИТС допускает эпизодическое обращение через точку в некритичном коде, а проект по умолчанию требует специальные методы БСП. См. `architecture.md` §4.

```bsl
// ❌ CRITICAL: полная загрузка объекта на каждый реквизит
ИНН = Контрагент.ИНН;
КПП = Контрагент.КПП;
Наименование = Контрагент.Наименование;

// ✅ ОПТИМАЛЬНО: один целевой запрос через БСП
Реквизиты = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(
    Контрагент, "ИНН, КПП, Наименование");
ИНН = Реквизиты.ИНН;
КПП = Реквизиты.КПП;
Наименование = Реквизиты.Наименование;
```

**Справка по методам БСП:** `architecture.md` §4.

### 3. Подзапрос в списке выбора

**Влияние:** выполнение запроса по принципу N+1
**Приоритет:** CRITICAL

```bsl
// ❌ CRITICAL: подзапрос выполняется на каждую строку
"ВЫБРАТЬ
|   Заказы.Ссылка,
|   (ВЫБРАТЬ СУММА(Оплаты.Сумма)
|    ИЗ Документ.Оплата КАК Оплаты
|    ГДЕ Оплаты.Заказ = Заказы.Ссылка) КАК СуммаОплат
|ИЗ
|   Документ.Заказ КАК Заказы"

// ✅ ОПТИМАЛЬНО: одно соединение с агрегацией
"ВЫБРАТЬ
|   Заказы.Ссылка КАК Ссылка,
|   ЕСТЬNULL(Оплаты.СуммаОплат, 0) КАК СуммаОплат
|ИЗ
|   Документ.Заказ КАК Заказы
|       ЛЕВОЕ СОЕДИНЕНИЕ (
|           ВЫБРАТЬ
|               Оплаты.Заказ КАК Заказ,
|               СУММА(Оплаты.Сумма) КАК СуммаОплат
|           ИЗ
|               Документ.Оплата КАК Оплаты
|           СГРУППИРОВАТЬ ПО
|               Оплаты.Заказ) КАК Оплаты
|       ПО Заказы.Ссылка = Оплаты.Заказ"
```

### 3a. Коррелированный подзапрос в ГДЕ (полусоединение на каждую строку)

**Влияние:** подзапрос выполняется для каждой строки внешнего источника; на больших таблицах квадратичный рост
**Приоритет:** CRITICAL

```bsl
// ❌ CRITICAL: ИСТИНА В (ВЫБРАТЬ ПЕРВЫЕ 1 ...) выполняется на каждую строку
"ВЫБРАТЬ ...
|ИЗ
|   РегистрСведений.ЗначенияПоУмолчанию КАК Значения
|ГДЕ
|   ИСТИНА В (ВЫБРАТЬ ПЕРВЫЕ 1 ИСТИНА
|       ИЗ Справочник.ГруппыДоступа.Пользователи КАК ГП
|       ГДЕ ГП.Ссылка = Значения.ГруппаДоступа
|           И ГП.Пользователь = &Пользователь)"

// ✅ ОПТИМАЛЬНО: собрать независимый набор один раз → проиндексировать → внутреннее соединение
"ВЫБРАТЬ РАЗЛИЧНЫЕ ГП.Ссылка КАК ГруппаДоступа
|ПОМЕСТИТЬ ВТ_ГруппыПользователя
|ИЗ Справочник.ГруппыДоступа.Пользователи КАК ГП
|ГДЕ ГП.Пользователь = &Пользователь
|ИНДЕКСИРОВАТЬ ПО ГруппаДоступа
|;
|ВЫБРАТЬ ...
|ИЗ РегистрСведений.ЗначенияПоУмолчанию КАК Значения
|   ВНУТРЕННЕЕ СОЕДИНЕНИЕ ВТ_ГруппыПользователя КАК Группы
|   ПО Группы.ГруппаДоступа = Значения.ГруппаДоступа"
```

Общий принцип: если соединение питает `СГРУППИРОВАТЬ ПО` по большому источнику, сначала соединить в проиндексированную временную таблицу, затем группировать.

## Антипаттерны высокого приоритета

### 4. Фильтр виртуальной таблицы в ГДЕ

**Влияние:** полное сканирование таблицы вместо использования индекса
**Приоритет:** HIGH

```bsl
// ❌ HIGH: фильтр после расчета виртуальной таблицы
"ВЫБРАТЬ
|   Остатки.Номенклатура КАК Номенклатура,
|   Остатки.КоличествоОстаток КАК Остаток
|ИЗ
|   РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки
|ГДЕ
|   Остатки.Склад = &Склад"

// ✅ ОПТИМАЛЬНО: фильтр в параметрах виртуальной таблицы
"ВЫБРАТЬ
|   Остатки.Номенклатура КАК Номенклатура,
|   Остатки.КоличествоОстаток КАК Остаток
|ИЗ
|   РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад) КАК Остатки"
```

### 5. Отсутствие ПЕРВЫЕ N

**Влияние:** загружаются все записи, хотя нужна только часть
**Приоритет:** HIGH

```bsl
// ❌ HIGH: загружает все записи
"ВЫБРАТЬ
|   Контрагенты.Ссылка КАК Ссылка
|ИЗ
|   Справочник.Контрагенты КАК Контрагенты"

// ✅ ОПТИМАЛЬНО: ограничение на уровне запроса
"ВЫБРАТЬ ПЕРВЫЕ 10
|   Контрагенты.Ссылка КАК Ссылка
|ИЗ
|   Справочник.Контрагенты КАК Контрагенты
|
|УПОРЯДОЧИТЬ ПО
|   Контрагенты.Наименование"
```

`ПЕРВЫЕ N` всегда сочетать с `УПОРЯДОЧИТЬ ПО`: без явной сортировки возвращаемое подмножество недетерминировано и может отличаться между запусками и СУБД.

### 5a. Непроиндексированная временная таблица в соединении или объединении

**Влияние:** сканирование временной таблицы на каждую присоединяемую строку; дорогая дедупликация в `ОБЪЕДИНИТЬ`
**Приоритет:** HIGH

У временной таблицы по умолчанию нет индексов. Если она позже участвует в `СОЕДИНЕНИИ` (худший случай), дедупликации `ОБЪЕДИНИТЬ` или фильтре `В (ВЫБРАТЬ ...)`, ее нужно создавать с `ИНДЕКСИРОВАТЬ ПО` по ключам соединения или дедупликации. Индексировать **2-3 наиболее селективных поля**, а не весь список колонок.

```bsl
// ❌ HIGH: ВТ соединяется в следующем пакете, индекса нет
"ВЫБРАТЬ ... ПОМЕСТИТЬ ВТ_Ключи ИЗ &Таблица КАК Т"

// ✅ ОПТИМАЛЬНО
"ВЫБРАТЬ ... ПОМЕСТИТЬ ВТ_Ключи ИЗ &Таблица КАК Т
|ИНДЕКСИРОВАТЬ ПО
|   Номенклатура, Склад"
```

### 6. Избыточные клиент-серверные вызовы

**Влияние:** сетевые накладные расходы, сериализация контекста
**Приоритет:** HIGH

```bsl
// ❌ HIGH: несколько серверных вызовов
&НаКлиенте
Процедура Обработать(Команда)
    Данные1 = ПолучитьДанные1НаСервере();
    Данные2 = ПолучитьДанные2НаСервере();
    Данные3 = ПолучитьДанные3НаСервере();
КонецПроцедуры

// ✅ ОПТИМАЛЬНО: один серверный вызов
&НаКлиенте
Процедура Обработать(Команда)
    ВсеДанные = ПолучитьВсеДанныеНаСервере();
КонецПроцедуры

&НаСервереБезКонтекста
Функция ПолучитьВсеДанныеНаСервере()
    Результат = Новый Структура;
    Результат.Вставить("Данные1", ПолучитьДанные1());
    Результат.Вставить("Данные2", ПолучитьДанные2());
    Результат.Вставить("Данные3", ПолучитьДанные3());
    Возврат Результат;
КонецФункции
```

### 7. &НаСервере вместо &НаСервереБезКонтекста

**Влияние:** лишняя передача контекста формы
**Приоритет:** HIGH

```bsl
// ❌ HIGH: передается полный контекст формы
&НаСервере
Функция ПолучитьДанныеНаСервере()
    Возврат ВыполнитьЗапрос();
КонецФункции

// ✅ ОПТИМАЛЬНО: без передачи контекста
&НаСервереБезКонтекста
Функция ПолучитьДанныеНаСервере(Параметры)
    Возврат ВыполнитьЗапрос(Параметры);
КонецФункции
```

### 7a. Сообщить() для уведомлений пользователя

**Влияние:** обходит подсистему сообщений пользователю платформы; сообщения не привязаны к полям формы, не собираются длительными операциями и ведут себя по-разному в тонком, веб- и мобильном клиентах.
**Приоритет:** HIGH
**Правило-источник:** `code-style.md`, «Запрещенные вызовы и конструкции» (`Сообщить()` для уведомлений пользователя **ЗАПРЕЩЕНА**).

```bsl
// ❌ HIGH: устаревший глобальный вызов, не привязан к полям формы, теряется в длительных операциях
Сообщить("Контрагент не указан");

// ✅ ОПТИМАЛЬНО (сервер): штатная подсистема сообщений, можно указать поле формы
Сообщение = Новый СообщениеПользователю;
Сообщение.Текст = НСтр("ru = 'Контрагент не указан'");
Сообщение.Поле = "Объект.Контрагент";
Сообщение.УстановитьДанные(ОбъектДляФормы);
Сообщение.Сообщить();

// ✅ ОПТИМАЛЬНО (обертки БСП - предпочтительно, когда БСП доступна)
ОбщегоНазначения.СообщитьПользователю(
    НСтр("ru = 'Контрагент не указан'"), , "Объект.Контрагент");
// На клиенте:
ОбщегоНазначенияКлиент.СообщитьПользователю(
    НСтр("ru = 'Контрагент не указан'"), , "Объект.Контрагент");
```

## Антипаттерны среднего приоритета

### 7b. Лишний РАЗЛИЧНЫЕ (объединение и группировка уже дедуплицируют)

**Влияние:** дополнительные проходы сортировки и группировки по тем же данным
**Приоритет:** MEDIUM

`ОБЪЕДИНИТЬ` (без `ВСЕ`) схлопывает дубликаты по объединенному результату, поэтому `РАЗЛИЧНЫЕ` внутри его операндов - мертвый груз. `РАЗЛИЧНЫЕ` вместе с `СГРУППИРОВАТЬ ПО` по тем же полям столь же избыточно. Когда дубликаты невозможны, использовать `ОБЪЕДИНИТЬ ВСЕ` и убрать дедупликацию совсем.

```bsl
// ❌ MEDIUM: тройная дедупликация - РАЗЛИЧНЫЕ в обоих операндах + схлопывание объединения
"ВЫБРАТЬ РАЗЛИЧНЫЕ ... ИЗ ВТ_Движения
|ОБЪЕДИНИТЬ
|ВЫБРАТЬ РАЗЛИЧНЫЕ ... ИЗ РегистрНакопления.Запасы"

// ✅ ОПТИМАЛЬНО: одна дедупликация самим объединением
"ВЫБРАТЬ ... ИЗ ВТ_Движения
|ОБЪЕДИНИТЬ
|ВЫБРАТЬ ... ИЗ РегистрНакопления.Запасы"
```

### 8. Отсутствие кеширования

**Влияние:** повторение дорогих операций
**Приоритет:** MEDIUM

```bsl
// ❌ MEDIUM: одно и то же вычисление повторяется
Для Каждого Строка Из ТаблицаДанных Цикл
    Курс = ПолучитьКурсВалюты(Строка.Валюта, Строка.Дата);
КонецЦикла;

// ✅ ОПТИМАЛЬНО: результаты кешируются
КэшКурсов = Новый Соответствие;

Для Каждого Строка Из ТаблицаДанных Цикл

    Ключ = Строка.Валюта + "|" + Формат(Строка.Дата, "ДФ=yyyyMMdd");
    Курс = КэшКурсов.Получить(Ключ);

    Если Курс = Неопределено Тогда
        Курс = ПолучитьКурсВалюты(Строка.Валюта, Строка.Дата);
        КэшКурсов.Вставить(Ключ, Курс);
    КонецЕсли;

КонецЦикла;
```

### 9. Алгоритм O(n²)

**Влияние:** квадратичный рост числа сравнений и времени выполнения при росте обеих коллекций
**Приоритет:** MEDIUM

```bsl
// ❌ MEDIUM: вложенный цикл поиска O(n²)
Для Каждого Строка1 Из Таблица1 Цикл
    Для Каждого Строка2 Из Таблица2 Цикл
        Если Строка1.Ключ = Строка2.Ключ Тогда
            // Обработка совпадения
        КонецЕсли;
    КонецЦикла;
КонецЦикла;

// ✅ ОПТИМАЛЬНО: O(n) с поиском по Соответствию
ИндексТаблицы2 = Новый Соответствие;
Для Каждого Строка2 Из Таблица2 Цикл
    ИндексТаблицы2.Вставить(Строка2.Ключ, Строка2);
КонецЦикла;

Для Каждого Строка1 Из Таблица1 Цикл
    Строка2 = ИндексТаблицы2.Получить(Строка1.Ключ);
    Если Строка2 <> Неопределено Тогда
        // Обработка совпадения
    КонецЕсли;
КонецЦикла;
```

### 10. Глубокая вложенность

**Влияние:** плохая читаемость, сложность сопровождения
**Приоритет:** MEDIUM

```bsl
// ❌ MEDIUM: глубокая вложенность (более 4 уровней)
Если Условие1 Тогда
    Если Условие2 Тогда
        Если Условие3 Тогда
            Если Условие4 Тогда
                // Логика
            КонецЕсли;
        КонецЕсли;
    КонецЕсли;
КонецЕсли;

// ✅ ОПТИМАЛЬНО: ранние возвраты
Если НЕ Условие1 Тогда
    Возврат;
КонецЕсли;

Если НЕ Условие2 Тогда
    Возврат;
КонецЕсли;

Если НЕ Условие3 Тогда
    Возврат;
КонецЕсли;

Если НЕ Условие4 Тогда
    Возврат;
КонецЕсли;

// Логика
```

## Архитектурные антипаттерны

### Большой ком грязи

- Нет четкой структуры
- Все зависит от всего
- **Влияние:** неподдерживаемость, высокий риск изменений

### Божественный модуль

- Один модуль делает все
- Сотни процедур в одном модуле
- **Влияние:** сложно понять, тестировать и менять

### Жесткая связанность

- Модули напрямую зависят от деталей реализации друг друга
- Изменения каскадно распространяются по модулям
- **Влияние:** высокая стоимость изменений

### Архитектура копипаста

- Один и тот же код в нескольких местах
- Нет общих модулей
- **Влияние:** рассогласованность, нагрузка на сопровождение

### Преждевременная оптимизация

- Сложное кеширование без доказанной необходимости
- Избыточное проектирование под текущий масштаб
- **Влияние:** ненужная сложность

## Оптимизированные паттерны

### Пакетный запрос с временной таблицей

```bsl
МенеджерВТ = Новый МенеджерВременныхТаблиц;

Запрос = Новый Запрос;
Запрос.МенеджерВременныхТаблиц = МенеджерВТ;

// Шаг 1: создать временную таблицу из входных данных
Запрос.Текст =
"ВЫБРАТЬ
|   Данные.Номенклатура КАК Номенклатура,
|   Данные.Склад КАК Склад
|ПОМЕСТИТЬ ВТ_Входные
|ИЗ
|   &ТаблицаДанных КАК Данные";
Запрос.УстановитьПараметр("ТаблицаДанных", ТаблицаДанных);
Запрос.Выполнить();

// Шаг 2: соединить с регистром для пакетного результата
Запрос.Текст =
"ВЫБРАТЬ
|   ВТ_Входные.Номенклатура КАК Номенклатура,
|   ВТ_Входные.Склад КАК Склад,
|   ЕСТЬNULL(Остатки.КоличествоОстаток, 0) КАК Остаток
|ИЗ
|   ВТ_Входные КАК ВТ_Входные
|       ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки(
|           ,
|           (Номенклатура, Склад) В
|               (ВЫБРАТЬ ВТ.Номенклатура, ВТ.Склад ИЗ ВТ_Входные КАК ВТ)
|       ) КАК Остатки
|       ПО ВТ_Входные.Номенклатура = Остатки.Номенклатура
|           И ВТ_Входные.Склад = Остатки.Склад";
РезультатЗапроса = Запрос.Выполнить();
```

### Пакетное получение реквизитов через БСП

```bsl
// Вместо отдельных вызовов в цикле
СписокКонтрагентов = ТаблицаДанных.ВыгрузитьКолонку("Контрагент");

// Получить все реквизиты одним вызовом
ТаблицаРеквизитов = ОбщегоНазначения.ЗначенияРеквизитовОбъектов(
    СписокКонтрагентов, "ИНН, КПП, Наименование");

// Построить соответствие для поиска
СоответствиеРеквизитов = Новый Соответствие;
Для Каждого СтрокаРеквизитов Из ТаблицаРеквизитов Цикл
    СоответствиеРеквизитов.Вставить(
        СтрокаРеквизитов.Ссылка, СтрокаРеквизитов);
КонецЦикла;
```

## Оценка уверенности (для ревью)

Оценивать находки по шкале от 0 до 100:

| Оценка | Описание |
|-------|-------------|
| **0-25** | Низкая уверенность - возможно ложное срабатывание |
| **26-50** | Умеренная - стоит обсудить |
| **51-75** | Высокая - вероятная реальная проблема |
| **76-100** | Очень высокая - подтвержденная проблема с доказательствами |

**Сообщать только о находках с уверенностью не менее 75 при ревью кода и не менее 50 при ревью архитектуры.**

## Краткий чек-лист

| Антипаттерн | Приоритет | Что искать |
|--------------|----------|-----------|
| Запрос в цикле | CRITICAL | `Для Каждого`, внутри которого `Новый Запрос` |
| Обращение через точку | CRITICAL | `.Реквизит` у ссылок |
| Подзапрос в списке выбора | CRITICAL | Вложенный `ВЫБРАТЬ` в перечне полей |
| Фильтр виртуальной таблицы в ГДЕ | HIGH | Условия по результату виртуальной таблицы |
| Нет ПЕРВЫЕ N | HIGH | Большие запросы без `ПЕРВЫЕ` |
| Несколько серверных вызовов | HIGH | Последовательные вызовы `НаСервере` с клиента |
| Неверное `&НаСервере` | HIGH | Серверный вызов, которому не нужен контекст формы |
| `Сообщить()` для уведомлений | HIGH | Прямой `Сообщить("...")` вместо `СообщениеПользователю` / `ОбщегоНазначения.СообщитьПользователю` |
| Нет кеша | MEDIUM | Повторяющиеся дорогие вызовы с теми же параметрами |
| Циклы O(n²) | MEDIUM | Вложенные циклы поиска совпадений |
| Глубокая вложенность | MEDIUM | Более 4 уровней условий и циклов |
