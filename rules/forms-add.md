# Добавление и изменение управляемой формы

Этот файл владеет **правилами**, а не порядком работы с инструментами.

## Правила создания и изменения формы

- **Создание и структурное изменение `Form.xml`** выполнять штатным инструментом работы с метаданными (1C:EDT, Конфигуратор или инструмент вашего агента), который сам следит за кодировкой, генерацией идентификаторов и порядком `ChildObjects`. Ручная правка XML допустима только точечно (однозначное исправление в одну строку) либо если нужного инструмента нет; во втором случае явно сообщить об этом пользователю один раз.
- **Проверка корректности обязательна** после любой правки XML: убедиться, что форма загружается и открывается в среде разработки. Форма, которая «разбирается» в вашем редакторе, не обязательно загрузится в Конфигураторе.
- **Именование элементов формы.** Элементы, добавляемые на типовую форму, должны иметь префикс `{PREFIX}` из `../project-profile.md`. Внутри вновь созданной формы (объект уже с префиксом) префикс на каждом элементе **не повторяется**: см. `metadata-naming.md`, «Именование метаданных».
- **Структура областей модуля формы** - `module-structure.md`, «Модуль формы» (5 обязательных областей).

## Правила представления формы

### Программная модификация типовых форм

Все изменения типовых форм выполняются **программно**, а не визуально. Элементы создаются в обработчике `ПриСозданииНаСервере` (либо через подписку или расширение).

### Размещение добавленных элементов

- Если у формы есть закладки, добавлять элементы на отдельную закладку (например, «Дополнительно» или с `{PREFIX}`).
- Если закладок нет, создавать группу без заголовка для добавленных элементов.
- Имена элементов типовой формы - с префиксом `{PREFIX}`.

### Новые формы (нетиповые объекты)

- Разделять реквизиты шапки и табличные части по отдельным закладкам: «Основное» (шапка), затем по одной закладке на каждую табличную часть.
- Заполнять свойство «Путь к данным шапки» для страниц с табличными частями.
- Ссылочные поля - максимальная ширина 27 символов.
- Многострочные поля комментария - ширина 79, высота 3.

### Проверка заполнения

- Использовать свойство «Проверка заполнения» реквизитов формы.
- Перед записью или проведением вызывать `ПроверитьЗаполнение()`:

```bsl
Если Не ПроверитьЗаполнение() Тогда
	Возврат;
КонецЕсли;
```

### Команды формы

- Для команд, изменяющих данные, включать флаг «Изменяет хранимые данные».
