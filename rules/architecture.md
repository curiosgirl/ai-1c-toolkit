# Стандарты разработки: архитектура и платформа

## 1. Архитектурные паттерны

### Размещение кода

- Бизнес-логика - **в общих модулях**, а не в модулях форм.
- Имена общих модулей следуют суффиксной конвенции БСП: без суффикса - только серверный модуль (`РаботаСЗаказами`); `Клиент` - только клиентский (`РаботаСЗаказамиКлиент`); `КлиентСервер` - компилируется с обеих сторон; `ВызовСервера` - серверный модуль, вызываемый с клиента; `Глобальный` - глобальный клиентский модуль; `ПовтИсп` - повторное использование возвращаемых значений; `Переопределяемый` - точки переопределения проекта.
- Серверные модули объектов - обязательный препроцессор: `#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда`.

### Паттерн «Структура результата»

Составной результат возвращать структурой:

```bsl
Результат = Новый Структура;
Результат.Вставить("ПроверкаПройдена", ПроверкаПройдена);
Результат.Вставить("ТекстОшибки", ТекстОшибки);
Возврат Результат;
```

### Паттерн «Ранний возврат»

Уменьшать вложенность, выходя сразу при невыполнении предусловий:

```bsl
Если Отказ Тогда
	Возврат;
КонецЕсли;

Если Не ЗначениеЗаполнено(ДатаДействия) Тогда
	Возврат ЗначениеПоУмолчанию;
КонецЕсли;
```

### Паттерн «Поиск в таблице значений»

```bsl
СтруктураОтбора = Новый Структура("Номенклатура", ТекущаяСтрока.Номенклатура);
НайденныеСтроки = ТаблицаДанных.НайтиСтроки(СтруктураОтбора);
Если НайденныеСтроки.Количество() = 0 Тогда
	Продолжить;
КонецЕсли;
```

### Подписки на события

Предпочтительнее изменения типовых модулей. Все методы подписок - через общий модуль `{PREFIX}ПодпискиНаСобытия`.

### Размещение новых объектов метаданных

Определяется параметром `{NEW_OBJECTS_IN}` из `../project-profile.md`:

| `{NEW_OBJECTS_IN}` | Поведение |
|---|---|
| `main_configuration` | Новые объекты - в основную конфигурацию. Расширение - только для перехвата событий |
| `extension` | Новые объекты можно размещать в расширении. Основную конфигурацию без явного указания не менять |

По умолчанию: `main_configuration`.

### Фоновые задания

Операции длительностью более 10 секунд переносить в фоновые задания с индикацией прогресса. Не блокировать интерфейс.

### Защитная проверка типов

В BSL нет строгой типизации. Когда это критично, проверять тип на входе функции:

```bsl
Если ТипЗнч(ДокументыИлиСсылка) <> Тип("Массив") Тогда
	Документы = Новый Массив;
	Документы.Добавить(ДокументыИлиСсылка);
Иначе
	Документы = ДокументыИлиСсылка;
КонецЕсли;
```

### Безопасное обращение к свойствам структуры

Всегда проверять наличие ключа перед обращением:

```bsl
Если ПараметрыОтчета.Свойство("ДатаНачала", ДатаНачала) Тогда
	// используем ДатуНачала
КонецЕсли;
```

### Нормализация коллекций

Приводить вход к одному типу коллекции для единообразной обработки. Для преобразования одиночного значения в массив использовать `ОбщегоНазначенияКлиентСервер.ЗначениеВМассиве()` (БСП).

### Использование подсистем БСП

При разработке механизмов на базе БСП (`{USES_BSP} = Да`) руководствоваться специализированными навыками:
- `skills/bsp-api/SKILL.md` — поиск модулей, сигнатур и проверка вызовов через `python skills/bsp-api/scripts/bsp-api.py check <Модуль.Метод>`. Запрещено вызывать несуществующие методы БСП.
- `skills/bsp-patterns/SKILL.md` — типовые сценарии применения 38 механизмов БСП (фоновые и длительные операции, печать документов, управление доступом, версионирование, присоединенные файлы).

## 2. Расширения

### Приоритет способов изменения

1. **Подписки на события** (предпочтительно)
2. **Расширения**
3. **Изменение типового кода** (в последнюю очередь)

### Директивы расширений

- `&Перед` / `&После` - предпочтительны для простого перехвата.
- `&Вместо` - полная замена метода; вызывать `ПродолжитьВызов(...)`, когда оригинал все же должен выполниться (без него выполнится только тело расширения).
- `&ИзменениеИКонтроль` - только когда тело метода нужно править по месту; маркеры изменений (`#Вставка` / `#Удаление`) **обязательны**; `ПродолжитьВызов()` **не** использовать: тело перехватчика - контролируемая копия оригинала.

### Правила размещения (когда `{NEW_OBJECTS_IN} = main_configuration`)

- Новые объекты метаданных - в основную конфигурацию.
- Новые реквизиты типовых объектов - в основную конфигурацию.
- Роли - в основную конфигурацию.

Независимо от `{NEW_OBJECTS_IN}`:

- Типовые роли **НЕ изменять** (создавать новые с `{PREFIX}`).

### Формы в расширениях

Визуальное редактирование форм в расширениях - **минимизировать**. Изменения - программно, через код.

## 3. Стандарты платформы

### Асинхронность и модальность

- Модальные вызовы **ЗАПРЕЩЕНЫ**: `Вопрос()`, `Предупреждение()`, `ВвестиЧисло()`, `ВвестиСтроку()`, `ВвестиДату()`, `ВвестиЗначение()`, `ОткрытьЗначение()` и любые другие синхронные блокирующие диалоги.
- Подход зависит от `{PLATFORM_VERSION}` из профиля проекта:

| `{PLATFORM_VERSION}` | Подход |
|---|---|
| менее 8.3.18 | `ОписаниеОповещения` (обратный вызов) |
| 8.3.18 и выше | `Асинх` / `Ждать` (предпочтительно) |

- Внутри `Асинх` процедур использовать ТОЛЬКО асинхронные аналоги. Смешивание `Асинх` / `Ждать` с неасинхронными методами **ЗАПРЕЩЕНО**.
- Любые вызовы диалогов на сервере **ЗАПРЕЩЕНЫ**.

### Клиент-серверное взаимодействие

- **`&НаСервереБезКонтекста` ОБЯЗАТЕЛЬНА** для всех серверных методов, которые не обращаются к данным формы. `&НаСервере` допустима только когда метод напрямую читает или пишет реквизиты и элементы формы.
- Если методу нужно только значение реквизита формы, передать его параметром и использовать `&НаСервереБезКонтекста`.

### Безопасность

- `Выполнить()` и `Вычислить()` - **ЗАПРЕЩЕНЫ** без крайней необходимости.
- **Зашитые учетные данные ЗАПРЕЩЕНЫ**: пароли, токены, ключи API в коде недопустимы. Хранить через подсистему безопасного хранилища БСП или защищенные от записи константы конфигурации.
- **RLS** - проектировать с учетом требований к ограничению доступа.

### Обработка ошибок

- Локализация строк - `НСтр("ru = '...'")` вместе с `СтроковыеФункцииКлиентСервер.ПодставитьПараметрыВСтроку()`.
- Ошибки собирать в одну переменную через `Символы.ПС`.
- Логирование - `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`, а НЕ `КраткоеПредставлениеОшибки()`.
- Пустые обработчики исключений **ЗАПРЕЩЕНЫ**: всегда записывать в журнал или пробрасывать дальше.

> **Позитивное дополнение - `logging-strategy.md`.** Этот раздел - про запреты и минимальные стандарты обработки ошибок. Позитивная часть (когда вообще писать в журнал регистрации, уровни важности, именование категорий событий `<Подсистема>.<Операция>.<Результат>`, структурированные данные через `ДанныеЖурналаРегистрации`, запреты на секреты и персональные данные, ротация) - в `logging-strategy.md`. Читать оба файла при добавлении или ревью кода обработки ошибок.

### Даты

- На сервере - `ТекущаяДатаСеанса()` вместо `ТекущаяДата()`. См. `platform-solutions.md`, раздел «Время на сервере».

### Запросы

- Проверять метаданные (наличие, имена, типы реквизитов) **до** написания запроса. Если в среде есть поиск по метаданным, использовать его. Имена реквизитов и табличных частей не придумывать.
- Перед написанием сложных запросов искать существующие примеры запросов (в кодовой базе и шаблонах).
- Текст запроса оформлять на новой строке на том же уровне отступа, что и объявление переменной:

```bsl
Запрос = Новый Запрос;
Запрос.Текст =
"ВЫБРАТЬ
|	Контрагенты.Ссылка КАК Ссылка,
|	Контрагенты.ИНН КАК ИНН
|ИЗ
|	Справочник.Контрагенты КАК Контрагенты";
```

- Всегда использовать промежуточную переменную для результата запроса. Цепочки вызовов **ЗАПРЕЩЕНЫ**:
  - Правильно: `РезультатЗапроса = Запрос.Выполнить();`
  - Неправильно: `Запрос.Выполнить().Выгрузить()` / `Запрос.Выполнить().Выбрать()`.
- Всегда использовать псевдонимы `КАК` для полей запроса (например, `Контрагенты.ИНН КАК ИНН`).
- **Запросы внутри циклов ЗАПРЕЩЕНЫ.** Использовать пакетные запросы с временными таблицами. См. `anti-patterns.md` §1 и шаблон «Пакетный запрос с временной таблицей».
- Использовать `Запрос.УстановитьПараметр()` вместо конкатенации строк: защита от инъекций и лучшее кеширование планов.
- Для сложной выборки данных предпочитать пакетные запросы с временными таблицами нескольким отдельным запросам.
- Временные таблицы называть с префиксом `ВТ_`.
- Тип соединения выбирать по требуемой семантике результата. `ВНУТРЕННЕЕ СОЕДИНЕНИЕ` - когда строки без совпадения нужно отбросить. `ЛЕВОЕ СОЕДИНЕНИЕ` - когда исходные строки нужно сохранить, при этом явно обрабатывать `NULL`.
- При обращении к регистрам фильтровать сначала по измерениям (в параметрах виртуальной таблицы, а не в `ГДЕ`).
- Движения регистров напрямую не менять, только через механизм проведения.
- Когда нужен ограниченный результат, использовать `ПЕРВЫЕ N`.
- Индексировать через метаданные все поля, участвующие в отборах и соединениях.
- **Временные таблицы, участвующие в соединении или `ОБЪЕДИНИТЬ`, должны быть проиндексированы.** Любая `ПОМЕСТИТЬ ВТ_*`, которая позже участвует в `СОЕДИНЕНИИ` (обязательно), в дедупликации `ОБЪЕДИНИТЬ` или в фильтре `В (ВЫБРАТЬ ...)` по большому набору, должна иметь `ИНДЕКСИРОВАТЬ ПО` по ключевым полям соединения или дедупликации. Индексировать **2-3 наиболее селективных поля**, а не весь список колонок: перечисление всех полей раздувает индекс и не улучшает план. См. `anti-patterns.md` §5a.
- **Сначала собрать, проиндексировать, потом соединять - перед тяжелой работой.** Заменять коррелированные подзапросы на строку (`ИСТИНА В (ВЫБРАТЬ ПЕРВЫЕ 1 ...)` в `ГДЕ`, подзапрос на каждую строку) временной таблицей, собранной один раз, проиндексированной и присоединенной через `ВНУТРЕННЕЕ СОЕДИНЕНИЕ`. Аналогично, если соединение питает `СГРУППИРОВАТЬ ПО` по большому источнику, сначала соединить в проиндексированную временную таблицу, затем группировать. См. `anti-patterns.md` §3a.
- `ОБЪЕДИНИТЬ` (без `ВСЕ`) уже дедуплицирует объединенный результат: `РАЗЛИЧНЫЕ` внутри его операндов избыточны и означают двойную работу. Когда дубликаты невозможны, предпочитать `ОБЪЕДИНИТЬ ВСЕ`. Также не сочетать `РАЗЛИЧНЫЕ` с `СГРУППИРОВАТЬ ПО` по тем же полям.

### Кроссплатформенность

- **COM-объекты** (`Новый COMОбъект(...)`) **ЗАПРЕЩЕНЫ**, если явно не указаны в задаче.
- Для Excel использовать табличный документ или БСП, а не `Excel.Application`.
- Пути к файлам - через `/` или функции платформы; `\` не зашивать.

### Совместимость с версией платформы

- Перед использованием любого метода API платформы убедиться, что он существует в `{PLATFORM_VERSION}` из профиля проекта.
- Использование методов более новых версий без проверки **ЗАПРЕЩЕНО**.

## 4. Доступ к данным: реквизиты ссылок

**Прямое обращение к реквизитам через точку** (например, `Контрагент.ИНН`) загружает объект целиком из базы данных. **[Правило проекта - строже стандарта ИТС.]** Вне тривиальных обработчиков с единичным вызовом это жесткий запрет. В простом коде без цикла с одним-двумя реквизитами ИТС это допускает, но по умолчанию проект требует использовать специальные методы БСП.

Использовать следующие методы:

| Метод | Назначение | Пример |
|--------|---------|---------|
| `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` | Один реквизит одной ссылки | `ОбщегоНазначения.ЗначениеРеквизитаОбъекта(Контрагент, "ИНН")` |
| `ОбщегоНазначения.ЗначенияРеквизитовОбъекта` | Несколько реквизитов одной ссылки | `ОбщегоНазначения.ЗначенияРеквизитовОбъекта(Контрагент, "ИНН, Наименование")` |
| `ОбщегоНазначения.ЗначениеРеквизитаОбъектов` | Один реквизит нескольких ссылок | `ОбщегоНазначения.ЗначениеРеквизитаОбъектов(Контрагенты, "ИНН")` |
| `ОбщегоНазначения.ЗначенияРеквизитовОбъектов` | Несколько реквизитов нескольких ссылок | `ОбщегоНазначения.ЗначенияРеквизитовОбъектов(Контрагенты, "ИНН, КПП")` |

### Кеширование и пакетное получение

- Повторные обращения к реквизитам ссылок кешировать через `Соответствие`. Полный пример - `anti-patterns.md` §8 «Отсутствие кеширования».
- Для нескольких ссылок предпочитать пакетные запросы (`ОбщегоНазначения.ЗначенияРеквизитовОбъектов` или `ВЫБРАТЬ ... ГДЕ Ссылка В (&МассивСсылок)`) вместо вызовов по одной ссылке в цикле. Шаблон с временной таблицей - `anti-patterns.md`, «Пакетный запрос с временной таблицей».

## 5. Производительность: главное

Обязательный минимум. Подробный каталог антипаттернов с приоритетами - `anti-patterns.md`. Подводные камни платформы (длительные операции, временное хранилище, поиск в коллекциях, внешние компоненты) - `platform-solutions.md`. Теория управляемых блокировок и паттерны транзакций (режим управления блокировкой, неявные и явные транзакции, канонический порядок блокировок, предотвращение взаимоблокировок, диагностика по технологическому журналу) - в **`locks-and-transactions.md`**.

- **Серверные массовые операции.** Массовые операции выполнять на сервере; не делать клиент-серверные вызовы внутри циклов. Серверные методы, не обращающиеся к данным формы, - `&НаСервереБезКонтекста`.
- **Запросы.** Никогда в цикле: пакетные запросы и временные таблицы. `ПЕРВЫЕ N`, когда нужна только часть данных. Индексировать в метаданных каждое поле отбора и соединения.
- **Привилегированный режим.** `УстановитьПривилегированныйРежим(Истина)` только при необходимости и всегда в паре с `УстановитьПривилегированныйРежим(Ложь)`. Текущее состояние - `ПривилегированныйРежим()`.
- **Кеширование.** Повторяющиеся вычисления кешировать: `Соответствие` на вызов, параметры сеанса на сеанс, регистры сведений между сеансами. Реквизиты ссылок - через `ОбщегоНазначения.ЗначенияРеквизитов*` с кешем.
- **Коллекции.** Массовое заполнение - `ЗаполнитьЗначенияСвойств()`. Поиск: до ~100 элементов достаточно `Найти()` / `НайтиПоЗначению()`; от ~1000 элементов или в цикле - индекс на `Соответствие` (O(1)) либо `ТаблицаЗначений.Индексы.Добавить(...)` + `НайтиСтроки()`. См. `platform-solutions.md`, раздел «Поиск в коллекциях: выбор по сложности».
- **Транзакции и управляемые блокировки.** Транзакции короткие; внутри - никакого взаимодействия с пользователем, длительных операций и внешних сервисов. Учитывать неявные транзакции (запись объекта открывает свою). Блокировать управляемые данные **до** чтения, затем читать, затем писать. Полный набор паттернов (проведение по нескольким регистрам, массовые операции, обновление журнала статусов) и проектный контракт порядка блокировок - `locks-and-transactions.md`. Разобранный пример проведения также в `platform-solutions.md`, раздел «Управляемые блокировки и предотвращение взаимоблокировок».

## 6. Запахи кода (полный каталог - `anti-patterns.md`)

| Запах | Признаки | Исправление |
|---|---|---|
| **Группы данных** | Одни и те же 3+ параметра передаются вместе в нескольких методах | Объединить в структуру через функцию-конструктор |
| **Одержимость примитивами** | Строки вместо перечислений, числовые коды вместо ссылок | Использовать `Перечисление`, `СправочникСсылка`, `ОпределяемыйТип` |
