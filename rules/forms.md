# Управляемые формы: точка входа

Этот файл - **роутер** для работы с управляемыми формами. Открывать первым, затем загружать только те файлы, которые выбирает таблица ниже. Сопутствующие файлы автоматически не подключаются.

> **Изменение `Form.xml`.** Сопутствующие правила определяют, *как должна выглядеть* корректная форма. Сама *правка* `Form.xml` и раскладки элементов делается штатным инструментом (1C:EDT, Конфигуратор или инструмент вашего агента для метаданных). Ручная правка XML допустима только точечно (однозначное исправление в одну строку) и обязательно с проверкой, что форма загружается. Правка логики `Form.Module.bsl` - обычная работа с BSL, и это ограничение на нее не распространяется.

## Маршрутизация

| Задача | Открыть |
|---|---|
| Спроектировать компоновку формы с нуля или в требованиях не указано размещение элементов | `form-patterns.md` |
| Создать или структурно изменить `Form.xml` | `forms-add.md` |
| Программная модификация типовых форм (размещение элементов, проверка заполнения, команды формы) | `forms-add.md`, «Правила представления формы» |
| Добавить или переименовать обработчики событий формы | `form-module.md`, «Добавление обработчиков событий формы» |
| Править логику `Form.Module.bsl` | `form-module.md` |
| Серверный код модуля формы (зарезервированные имена `ПараметрыВыбора`, `СвязиПараметровВыбора`, `СписокВыбора`, `ПараметрыОтбора`, `ОтборСтрок`) | `form-module.md`, «Зарезервированные имена» |
| Клиентский асинхронный код (`Асинх` / `Ждать`) | `async-methods.md` |

Каждый сопутствующий файл самодостаточен: загружать только подходящие задаче. Весь набор «на всякий случай» не читать.
