# Шаблон профиля проекта: параметры конфигурации и окружения

> Данный файл является **эталонным руководством и набором примеров** для настройки `project-profile.md` под конкретный проект 1С:Предприятие. При старте работы в новом репозитории скопируйте подходящий пример в `project-profile.md` и скорректируйте параметры под свою систему.

Параметры из `project-profile.md` определяют поведение ИИ-агентов при генерации кода, проверке метаданных, оптимизации запросов и работе с тестами.

---

## Справочник параметров

| Параметр | Назначение | Допустимые значения | Значение по умолчанию / Если пусто |
|---|---|---|---|
| `{PREFIX}` | Префикс для новых объектов метаданных, реквизитов типовых объектов, элементов форм, подсистем и ролей | Строка с подчеркиванием на конце (например, `смк_`, `мп_`, `ит_`) либо пустое значение | Если пусто: объекты создаются без префикса, `{PREFIX}` в шаблонах превращается в пустую строку |
| `{PLATFORM_VERSION}` | Версия платформы 1С:Предприятие (и режим совместимости конфигурации). Определяет доступность синтаксических возможностей платформы | Номер версии (например, `8.3.18`, `8.3.24`, `8.3.27`) | Если пусто: `8.3.25` (при возникновении сомнений агент уточняет у разработчика) |
| `{EDT_PROJECT_FORMAT}` | Структура каталогов исходных кодов 1С (EDT) в репозитории | `src/cf/src` (составные проекты), `src/configuration` (стандартный экспорт EDT), `.` (корень) | Если пусто: агент определяет путь по расположению `Configuration.mdo` |
| `{CONFIGURATION_TYPE}` | Тип конфигурации 1С: типовая или отраслевая основа | `ERP`, `КА`, `УТ`, `БП`, `ЗУП`, `УНФ`, `Самописная` | Если пусто: `Самописная` (агент не предполагает наличие типовых подсистем) |
| `{USES_BSP}` | Наличие и активное использование Библиотеки Стандартных Подсистем (БСП) | `Да` (`Истина`) / `Нет` (`Ложь`) | Если пусто: `Да`, если найден модуль `ОбщегоНазначения`, иначе `Нет` |
| `{LOCK_MODE}` | Режим управления транзакционными блокировками данных в конфигурации | `Managed` (Управляемый) / `Automatic` (Автоматический) | Если пусто: `Managed` (рекомендуемый платформенный стандарт) |
| `{TEST_FRAMEWORKS}` | Фреймворки автоматизированного тестирования, используемые в проекте | `YAxUnit`, `Vanessa Automation`, перечень через запятую или `Отсутствуют` | Если пусто: `Отсутствуют` (тесты не генерируются без явного запроса) |
| `{NEW_OBJECTS_IN}` | Целевое размещение вновь создаваемых объектов метаданных | `main_configuration` (в основной конфигурации) или `extension` (в расширении) | Если пусто: `main_configuration` |

## Влияние параметров на генерацию кода и правила

1. **`{PREFIX}`**
   - *Задан:* новые справочники, документы, регистры, перечисления, реквизиты типовых объектов и элементы типовых форм именуются с этим префиксом (например, `{PREFIX}СуммаНДС`). Внутри собственных объектов реквизиты именуются **без** префикса.
   - *Пуст:* объекты и реквизиты создаются без префикса. Агент строго следит за отсутствием коллизий с существующими объектами конфигурации поставщика.

2. **`{PLATFORM_VERSION}`**
   - `>= 8.3.18`: в клиентском коде применяется современный асинхронный синтаксис `Асинх` / `Ждать` / `Обещание`, функции `*Асинх` (`ВопросАсинх`, `ПредупреждениеАсинх`, `НайтиФайлыАсинх`).
   - `< 8.3.18`: ключевые слова `Асинх` / `Ждать` не используются; диалоги и вызовы оформляются через `ОписаниеОповещения` и методы с обратным вызовом (`Показать*`, `Начать*`).
   - `>= 8.3.21`: доступен асинхронный HTTP (`ВызватьHTTPМетодАсинх` и др.).

3. **`{USES_BSP}`**
   - *Да / Истина:* обращение к реквизитам ссылочных объектов на сервере выполняется строго через `ОбщегоНазначения.ЗначениеРеквизитаОбъекта*`, фоновые задачи строятся на подсистеме `ДлительныеОперации`, работа со строками — через `СтроковыеФункцииКлиентСервер`. Прямое чтение через точку на сервере запрещено.
   - *Нет / Ложь:* функции БСП не вызываются. Для получения реквизитов формируются точечные запросы или проектные вспомогательные функции.

4. **`{LOCK_MODE}`**
   - *Managed:* перед чтением критичных данных и записью в транзакции агент формирует явные управляемые блокировки (`БлокировкаДанных`).
   - *Automatic:* управляемые блокировки платформы не используются, управление возлагается на СУБД, однако транзакции остаются максимально короткими.

5. **`{TEST_FRAMEWORKS}`**
   - *YAxUnit:* агент использует модули регистрации тестов (`ИсполняемыеСценарии`, `ЮТтесты.ВТранзакции()`), утверждения `ЮТест.ОжидаетЧто()`, фабрики подготовки тестовых данных.
   - *Vanessa Automation:* при разработке сценариев агент формирует сценарии поведения Gherkin в каталоге `tests/` (`*.feature`).

## Примеры конфигурации под разные типы проектов

### Пример 1. Корпоративное решение на базе 1С:ERP (EDT + БСП + YAxUnit + Vanessa)

Типичный стек крупного корпоративного внедрения (например, 1С:ERP Управление строительством / холдингом):

```markdown
# Профиль проекта

## Параметры проекта

| Параметр | Значение | Назначение | Если пусто |
|---|---|---|---|
| `{PREFIX}` | `смк_` | Префикс для новых объектов метаданных, реквизитов типовых объектов, элементов форм, ролей | Новые объекты создаются без префикса |
| `{PLATFORM_VERSION}` | `8.3.27` | Версия платформы и режим совместимости основной конфигурации | Спросить у пользователя при написании асинхронного кода |
| `{EDT_PROJECT_FORMAT}` | `src/cf/src` | Структура каталогов EDT для основной конфигурации | Определить по расположению Configuration.mdo |
| `{CONFIGURATION_TYPE}` | `ERP` | 1С:ERP Управление строительством 2.5 | Считать конфигурацию произвольной |
| `{USES_BSP}` | `Да` | Библиотека Стандартных Подсистем используется активно | Да |
| `{LOCK_MODE}` | `Managed` | Управляемый режим блокировок данных | Managed |
| `{TEST_FRAMEWORKS}` | `YAxUnit, Vanessa Automation` | Модульные тесты YAxUnit и сценарии Vanessa | Отсутствуют |
| `{NEW_OBJECTS_IN}` | `main_configuration` | Доработки ведутся непосредственно в основной конфигурации | main_configuration |

## Окружение

| Что | Значение |
|---|---|
| Формат исходников | EDT (`src/cf/src` — основная конфигурация, `yaxunit/src` — расширение тестов) |
| Режим блокировки | Управляемый (`Managed`), см. `rules/locks-and-transactions.md` |
| Наличие БСП | Да (`ОбщегоНазначения.*` используется повсеместно) |
| Тесты | YAxUnit (в расширении `yaxunit/src`), Vanessa Automation (`tests/**/*.feature`) |
```

### Пример 2. Разработка в расширении для типовой 1С:УТ / 1С:КА

Стек доработки типовой тиражной конфигурации без снятия с поддержки:

```markdown
# Профиль проекта

## Параметры проекта

| Параметр | Значение | Назначение | Если пусто |
|---|---|---|---|
| `{PREFIX}` | `мп_` | Префикс для новых объектов метаданных и реквизитов расширения | Новые объекты создаются без префикса |
| `{PLATFORM_VERSION}` | `8.3.24` | Версия платформы и режим совместимости базы | Спросить у пользователя при написании асинхронного кода |
| `{EDT_PROJECT_FORMAT}` | `src/configuration` | Исходники расширения в формате EDT | Определить по расположению Configuration.mdo |
| `{CONFIGURATION_TYPE}` | `УТ` | 1С:Управление торговлей 11.5 | Считать конфигурацию произвольной |
| `{USES_BSP}` | `Да` | Использование типовых механизмов БСП | Да |
| `{LOCK_MODE}` | `Managed` | Управляемые блокировки данных | Managed |
| `{TEST_FRAMEWORKS}` | `YAxUnit` | Модульные тесты YAxUnit | Отсутствуют |
| `{NEW_OBJECTS_IN}` | `extension` | Все новые объекты создаются строго в расширении | extension |

## Окружение

| Что | Значение |
|---|---|
| Формат исходников | EDT (расширение конфигурации в `src/configuration`) |
| Размещение доработок | `extension` |
| Режим блокировки | `Managed` |
| Наличие БСП | Да |
| Тесты | YAxUnit |
```

### Пример 3. Самописная база или Legacy-конфигурация без БСП

Стек нетиповой конфигурации без БСП с автоматическими блокировками:

```markdown
# Профиль проекта

## Параметры проекта

| Параметр | Значение | Назначение | Если пусто |
|---|---|---|---|
| `{PREFIX}` | ` ` | Без префикса (база полностью собственной разработки) | Новые объекты создаются без префикса |
| `{PLATFORM_VERSION}` | `8.3.20` | Версия платформы 1С:Предприятие | Спросить у пользователя при написании асинхронного кода |
| `{EDT_PROJECT_FORMAT}` | `src/cf/src` | Структура каталогов EDT | Определить по расположению Configuration.mdo |
| `{CONFIGURATION_TYPE}` | `Самописная` | Оригинальная учетная система без типовых метаданных 1С | Самописная |
| `{USES_BSP}` | `Нет` | БСП отсутствует (вызовы ОбщегоНазначения.* не применять) | Нет |
| `{LOCK_MODE}` | `Automatic` | Автоматический режим управления блокировками | Automatic |
| `{TEST_FRAMEWORKS}` | `Отсутствуют` | Автоматизированные тесты не подключены | Отсутствуют |
| `{NEW_OBJECTS_IN}` | `main_configuration` | Вся разработка ведется в основной конфигурации | main_configuration |

## Окружение

| Что | Значение |
|---|---|
| Формат исходников | EDT (`src/cf/src`) |
| Режим блокировки | `Automatic` |
| Наличие БСП | Нет (вместо БСП использовать точечные запросы и платформенные методы) |
| Тесты | Отсутствуют |
```
