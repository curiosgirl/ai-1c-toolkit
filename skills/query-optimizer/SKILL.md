# Оптимизация и аудит запросов 1С

Скилл предназначен для проектирования, рефакторинга и оптимизации запросов на языке запросов 1С:Предприятие в соответствии со стандартами разработки и требованиями к высокой производительности СУБД.

---

## 1. Нормативная база и правила проекта

При оптимизации запросов агент руководствуется следующими документами:
- `rules/query-design.md` - точка входа и чек-лист проектирования запросов.
- `rules/architecture.md` (раздел «Запросы») - жесткие обязательные правила (псевдонимы `КАК`, запрет склейки строк, промежуточная переменная).
- `rules/anti-patterns.md` - каталог дефектов производительности с оценкой влияния на СУБД.
- `rules/locks-and-transactions.md` - блокировки данных перед запросом при управляемом режиме (`Managed`).

## 2. Чек-лист аудита запроса

```mermaid
flowchart TD
    Q1[1. Проверка источников и метаданных] --> Q2[2. Запросы в циклах?]
    Q2 -- Да --> FixLoop[Вынести в единый запрос с В (&Список)]
    Q2 -- Нет --> Q3[3. Параметры виртуальных таблиц]
    Q3 -- Фильтр в ГДЕ --> FixVT[Перенести в параметры ВТ]
    Q3 -- OK --> Q4[4. Подзапросы в выборке / соединениях]
    FixLoop --> Q3
    FixVT --> Q4
    Q4 -- Есть --> FixSub[Перевести в ВТ с ИНДЕКСИРОВАТЬ ПО]
    Q4 -- Нет --> Q5[5. Избыточные РАЗЛИЧНЫЕ и ОБЪЕДИНИТЬ]
    FixSub --> Q5
    Q5 -- Есть --> FixDistinct[Удалить РАЗЛИЧНЫЕ / заменить на ОБЪЕДИНИТЬ ВСЕ]
    Q5 -- Нет --> Q6[6. Очистка tempdb: УНИЧТОЖИТЬ ВТ]
    FixDistinct --> Q6
    Q6 --> Q7[7. BSL-оформление: КАК, регистр, переменная]
```

### 1. Архитектура и исключение запросов в цикле
- **Запрет:** Выполнение запроса внутри любого цикла (`Для`, `Для Каждого`, `Пока`).
- **Решение:** Формирование массива ссылок, передача через `Запрос.УстановитьПараметр("МассивСсылок", Массив)` и единый запрос с условием `Ссылка В (&МассивСсылок)`.

### 2. Фильтрация виртуальных таблиц
- **Запрет:** Наложение условий на измерения и периоды в секции `ГДЕ` виртуальной таблицы (например, `ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки ГДЕ Остатки.Номенклатура = &Номенклатура`).
- **Причина:** Платформа сначала строит итоги по всему регистру на дату, и лишь затем отсекает строки через SQL WHERE.
- **Решение:** Перенос условий строго в параметры таблицы: `РегистрНакопления.ТоварыНаСкладах.Остатки(&Период, Номенклатура = &Номенклатура)`.

### 3. Подзапросы и индексация временных таблиц
- **Запрет 1:** Подзапросы в списке полей выборки `(ВЫБРАТЬ ...) КАК Поле` (вызывает N+1 чтений строк).
- **Запрет 2:** Соединение реальной таблицы с подзапросом `ЛЕВОЕ СОЕДИНЕНИЕ (ВЫБРАТЬ ...) КАК ВложенныйЗапрос`.
- **Решение:**
  1. Вынесение вложенной выборки в отдельный пакет с помещением во временную таблицу: `ПОМЕСТИТЬ ВТ_АгрегированныеДанные`.
  2. Обязательное добавление секции `ИНДЕКСИРОВАТЬ ПО` по полям будущего соединения (2-3 селективных поля).
  3. Соединение основной таблицы с созданной `ВТ_АгрегированныеДанные`.

### 4. Избыточные `РАЗЛИЧНЫЕ` и `ОБЪЕДИНИТЬ`
- **Запрет:** Использование `РАЗЛИЧНЫЕ` поверх группировки `СГРУППИРОВАТЬ ПО` или операндов `ОБЪЕДИНИТЬ`.
- **Причина:** Дополнительная тяжелая сортировка на диске в `tempdb` СУБД.
- **Решение:** Замена `ОБЪЕДИНИТЬ` на `ОБЪЕДИНИТЬ ВСЕ`, если уникальность гарантируется алгоритмом или дубли исключены на уровне источников.

### 5. Освобождение памяти tempdb (`УНИЧТОЖИТЬ`)
- Для пакетных запросов с промежуточными временными таблицами в конце пакета обязательна секция деструктора:
  ```sql
  УНИЧТОЖИТЬ ВТ_Товары;
  УНИЧТОЖИТЬ ВТ_Цены;
  ```
- Это предотвращает разрастание системной базы данных СУБД и высвобождает кэш планов.

### 6. Стандарты BSL-обвязки
- **Псевдонимы полей:** Каждое вычисляемое или составное поле обязано иметь явный псевдоним `КАК ИмяПоля`.
- **Регистр ключевых слов:** Ключевые слова пишутся заглавными буквами (`ВЫБРАТЬ`, `ИЗ`, `ГДЕ`, `ЛЕВОЕ СОЕДИНЕНИЕ`).
- **Промежуточная переменная:** Запрещена запись `Выборка = Запрос.Выполнить().Выбрать()`. Обязательно:
  ```bsl
  РезультатЗапроса = Запрос.Выполнить();
  Выборка = РезультатЗапроса.Выбрать();
  ```

## 3. Примеры рефакторинга «Было / Стало»

### Пример 1. Коррелированный подзапрос и фильтр в ГДЕ

```bsl
// ❌ НЕОПТИМАЛЬНО:
// 1) Фильтр виртуальной таблицы в ГДЕ (сканирование лишних строк)
// 2) Подзапрос в списке выборки (N+1 вычислений)
Запрос.Текст =
"ВЫБРАТЬ
|	Заказ.Ссылка КАК Ссылка,
|	(ВЫБРАТЬ СУММА(Оплаты.Сумма)
|	 ИЗ Документ.Оплата КАК Оплаты
|	 ГДЕ Оплаты.Заказ = Заказ.Ссылка) КАК СуммаОплаты
|ИЗ
|	Документ.ЗаказКлиента КАК Заказ
|	ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки
|		ПО Остатки.Номенклатура = Заказ.Номенклатура
|ГДЕ
|	Остатки.Склад = &Склад";
```

```bsl
// ✅ ОПТИМИЗИРОВАНО:
// 1) Фильтр склада перенесен в параметры виртуальной таблицы
// 2) Оплаты предварительно свернуты во временную таблицу с индексом
// 3) Временные таблицы освобождены через УНИЧТОЖИТЬ
Запрос.Текст =
"ВЫБРАТЬ
|	Оплаты.Заказ КАК Заказ,
|	СУММА(Оплаты.Сумма) КАК СуммаОплаты
|ПОМЕСТИТЬ ВТ_Оплаты
|ИЗ
|	Документ.Оплата КАК Оплаты
|ГДЕ
|	Оплаты.Заказ В (&МассивЗаказов)
|СГРУППИРОВАТЬ ПО
|	Оплаты.Заказ
|ИНДЕКСИРОВАТЬ ПО
|	Заказ
|;
|
|ВЫБРАТЬ
|	Заказ.Ссылка КАК Ссылка,
|	ЕСТЬNULL(ВТ_Оплаты.СуммаОплаты, 0) КАК СуммаОплаты
|ИЗ
|	Документ.ЗаказКлиента КАК Заказ
|	ЛЕВОЕ СОЕДИНЕНИЕ ВТ_Оплаты КАК ВТ_Оплаты
|		ПО ВТ_Оплаты.Заказ = Заказ.Ссылка
|	ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад) КАК Остатки
|		ПО Остатки.Номенклатура = Заказ.Номенклатура
|ГДЕ
|	Заказ.Ссылка В (&МассивЗаказов)
|;
|
|УНИЧТОЖИТЬ ВТ_Оплаты";
```

## 4. Порядок применения скилла

1. Изучить исходный текст запроса и задействованные структуры метаданных.
2. Проверить на соответствие чек-листу аудита (разделы 1-6).
3. Сформировать переработанный текст запроса.
4. Проверить установку параметров (типы параметров должны точно соответствовать типам полей метаданных).
5. При наличии синтакс-контроля или подключения к БД выполнить тестовый запуск запроса.
