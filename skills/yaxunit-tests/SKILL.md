# Разработка тестов на базе YAxUnit

Скилл регламентирует создание модульных (unit) и интеграционных тестов для 1С:Предприятие с использованием фреймворка YAxUnit.

---

## 1. Контекст и параметры проекта

- Наличие фреймворка: `{TEST_FRAMEWORKS}` содержит `YAxUnit` (см. `project-profile.md`).
- Соглашения и размещение: описаны в `rules/project-context.md`.
- Все стандарты чистоты кода (`rules/code-style.md`, `rules/architecture.md`) распространяются на тесты в полном объеме:
  - Запрещены `Сообщить()`, тернарный оператор `?(...)`, прямое обращение через точку от ссылки при БСП.
  - Для проверки возникновения ошибок используется метод `ЮТест.ОжидаетЧто(...).ВызываетИсключение(...)`, а не пустые блоки `Попытка...Исключение`.

---

## 2. Архитектура тестового модуля YAxUnit

Тестовый модуль представляет собой общий модуль (или модуль обработки в составе тестового расширения) со следующей структурой областей:

```bsl
#Область ОписаниеПеременных

Перем КонтекстНабора;

#КонецОбласти

#Область ПрограммныйИнтерфейс

// Экспортные процедуры тестирования (помеченные в ИсполняемыеСценарии)

#КонецОбласти

#Область СлужебныйПрограммныйИнтерфейс

// Обязательная точка входа для регистрации сценариев
Процедура ИсполняемыеСценарии() Экспорт
	// Регистрация тестов через текучий интерфейс ЮТтесты
КонецПроцедуры

#КонецОбласти

#Область СлужебныеПроцедурыИФункции

// Вспомогательные методы подготовки данных и очистки

#КонецОбласти
```

## 3. Регистрация сценариев в `ИсполняемыеСценарии`

```bsl
Процедура ИсполняемыеСценарии() Экспорт

	ИмяПодсистемы = "Продажи";

	ЮТтесты.ВТранзакции()
		.ДобавитьТестовыйНабор("РасчетСкидкиПоАкции", ИмяПодсистемы)
		.Тег("Модульные")
		.Перед("ПодготовитьДанные")
		.УдалениеТестовыхДанных()
		.После("ОчиститьДанные")
		.ДобавитьТест("ПроверитьРасчетПриПревышенииПорога", "Скидка должна применяться при сумме > 10000")
			.СПараметрами(15000, 1500)
		.ДобавитьТест("ПроверитьОтсутствиеСкидкиДоПорога", "Скидка равна 0 при сумме <= 10000")
			.СПараметрами(8000, 0)
		.ДобавитьТест("ПроверитьИсключениеПриОтрицательнойСумме", "Отрицательная сумма вызывает ошибку");

КонецПроцедуры
```

### Ключевые опции регистрации:
- `ВТранзакции()` - автоматический откат всех изменений БД по окончании набора. База данных остается чистой.
- `УдалениеТестовыхДанных()` - очистка созданных объектов.
- `Тег("Модульные" / "Интеграционные")` - фильтрация при пакетном прогоне в CI/CD.
- `.СПараметрами(...)` - передача параметров в процедуру теста для параметризованных проверок.

## 4. Паттерн AAA (Arrange - Act - Assert) и утверждения `ЮТест`

Каждый тестовый метод строится по трехфазной структуре AAA:

```bsl
Процедура ПроверитьРасчетПриПревышенииПорога(СуммаЗаказа, ОжидаемаяСкидка) Экспорт

	// 1. Arrange (Подготовка)
	Контекст = ЮТест.КонтекстТестовогоНабора();
	ПараметрыРасчета = Новый Структура;
	ПараметрыРасчета.Вставить("Сумма", СуммаЗаказа);
	ПараметрыРасчета.Вставить("Клиент", Контекст.ТестовыйКлиент);

	// 2. Act (Действие)
	ФактическаяСкидка = {PREFIX}РасчетСкидок.РассчитатьСкидку(ПараметрыРасчета);

	// 3. Assert (Проверка утверждения)
	ЮТест.ОжидаетЧто(ФактическаяСкидка, "Сумма рассчитанной скидки не соответствует условиям акции")
		.Равно(ОжидаемаяСкидка);

КонецПроцедуры
```

### Проверка генерации исключений:

```bsl
Процедура ПроверитьИсключениеПриОтрицательнойСумме() Экспорт

	ПараметрыРасчета = Новый Структура("Сумма", -100);

	ЮТест.ОжидаетЧто({PREFIX}РасчетСкидок)
		.Метод("РассчитатьСкидку", ПараметрыРасчета)
		.ВызываетИсключение("Сумма заказа не может быть отрицательной");

КонецПроцедуры
```

## 5. Подготовка тестовых данных (Фабрики)

1. **Не создавать объекты вручную дублирующимся кодом.**
   Использовать существующие фабрики тестов проекта:
   - Общие модули вида `{PREFIX}ГенерацияДанныхТестов`, `{PREFIX}ФабрикаДокументов`.
   - Если префикс `{PREFIX}` пуст в `project-profile.md`, модули именуются без префикса (`ГенерацияДанныхТестов`).
2. **Переиспользование данных:**
   Объекты, нужные для всей группы тестов, создаются в методе `.Перед("ПодготовитьДанные")` и сохраняются в `ЮТест.КонтекстТестовогоНабора()`.
3. **Фиктивные реквизиты:**
   Для генерации уникальных ИНН/КПП, наименований и кодов использовать генераторы уникальных идентификаторов (`Строка(Новый УникальныйИдентификатор)`).
